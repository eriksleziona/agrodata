# Organization and user foundation

## Scope

This initial identity domain introduces organization tenancy and
organization-scoped user records. It does not implement login, sessions, token
issuance, password hashing, password reset, or authorization enforcement.

## Persistence model

### Organizations

`organizations` contains:

| Column | Notes |
| --- | --- |
| `id` | UUID primary key generated by the application. |
| `name` | Required organization name. |
| `tax_id` | Required tax identifier with a database index. |
| `created_at`, `updated_at` | Timezone-aware UTC timestamps. |

### Users

`users` contains:

| Column | Notes |
| --- | --- |
| `id` | UUID primary key generated by the application. |
| `organization_id` | Required foreign key to `organizations.id`, indexed for tenant queries. |
| `email` | Required normalized email, unique together with `organization_id`. |
| `password_hash` | Required opaque credential-hash field; never included in output schemas. |
| `first_name`, `last_name` | Required display names. |
| `role` | PostgreSQL `user_role` enum. |
| `created_at`, `updated_at` | Timezone-aware UTC timestamps. |

The unique constraint permits the same email address in different organizations,
but not twice in one organization. `UserCreate` normalizes incoming emails by
trimming whitespace and converting them to lowercase before the constraint is
checked.

## Roles

| Role | Intended responsibility |
| --- | --- |
| `OWNER` | Organization ownership and future highest-level administration. |
| `ADMIN` | Organization administration. |
| `OPERATOR` | Operational machine and job workflows. |
| `FARMER` | Farm and field workflows. |
| `VIEWER` | Read-only access once authorization is introduced. |

Roles are stored now but are not yet enforced because authentication and
authorization are explicitly outside this feature.

## Layers

- `app.models` defines SQLAlchemy persistence entities and `UserRole`.
- `app.schemas` defines validated service/API boundary data. Output schemas omit
  `password_hash`.
- `app.repositories` contains database queries and never commits transactions.
- `app.services` coordinates invariants and transaction boundaries.

## Migration

Apply the domain migration after the database foundation migration:

```powershell
.\.venv\Scripts\alembic -c backend/alembic.ini upgrade head
```

`organizations`, and `users`, including its foreign key, indexes, and unique
constraint. It adds no authentication tables or application routes.
